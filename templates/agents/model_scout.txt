## Your job: make the model registry reflect the newest releases, today

The engine must always evaluate the newest generation of each tracked family. You have web
access: use it. For every family in `catalog/families.yaml`:

1. Find what is newest. Check the family's `sources` (Hugging Face author pages via the API,
   e.g. `https://huggingface.co/api/models?author=<author>&sort=lastModified&direction=-1&limit=200`,
   vendor blogs, release notes, API model lists) and general web search for releases in the last
   months. Cover every size tier the family ships (small, mid, large, MoE), not only the flagship.
2. Verify each candidate: for open weights, read the Hugging Face model info
   (`https://huggingface.co/api/models/<id>?blobs=true`: safetensors parameter total, weight bytes,
   license, gated, lastModified, pipeline tag) and the model card (chat template, thinking mode,
   context length, trust_remote_code needs, vLLM support notes). For API families, the provider's
   model list and the model/system card URL.
3. Decide what is a subject per the family's `scope`, and compute whether it fits one GPU:
   bf16_gb = 2 * params_b; fits if bf16_gb <= single_gpu_memory_gb * headroom (catalog policy).
