# Moonshot AI (Kimi K2 / K2.5 / K2.6 / K2.7 Code / K3 family, plus Kimi-VL, Kimi-Linear, Kimi-Audio, Kimi-Dev, Moonlight)

Fetched: 2026-10-19

Moonshot AI (北京月之暗面科技, Beijing; CEO Yang Zhilin 杨植麟) is a Chinese LLM startup whose consumer product is the Kimi chatbot (kimi.com) and whose developer platform is platform.moonshot.ai / platform.kimi.ai. Its open-weight flagship line is the 1T-parameter / 32B-active MoE "Kimi K2" family (K2-Base/Instruct Jul 2025, K2-Instruct-0905 Sep 2025, K2 Thinking Nov 2025, K2.5 multimodal Jan 2026, K2.6 Apr 2026, K2.7 Code Jun 2026) and, since July 2026, Kimi K3 (2.8T total / 104B active, native vision, 1M context, "Kimi K3 License"). Smaller open models: Moonlight-16B-A3B (Feb 2025), Kimi-VL-A3B (Apr/Jun 2025), MoonViT-SO-400M, Kimi-Audio-7B (Apr 2025), Kimi-Dev-72B (Jun 2025), Kimi-Linear-48B-A3B (Oct 2025). Weights live at https://huggingface.co/moonshotai (19 repos), code at https://github.com/MoonshotAI, tech reports on arXiv (K2: 2507.20534; K2.5: 2602.02276) or GitHub (K3: Kimi-K3/k3_tech_report.pdf), blogs at https://www.kimi.ai/blog, API docs at https://platform.kimi.ai/docs (index: /docs/llms.txt). Safety documentation is thin: the K2 report has a one-page Promptfoo-based red-team table; the K2.5 report has none; the K3 report has an internal cyber-capability evaluation and cites the UK AISI/CAISI assessment but no harmlessness evaluation; there is no safety framework, usage policy page (beyond platform Terms of Service), model card safety section, or published incident process.

### Not reported
Across the K2, K2.5 and K3 technical reports, all 19 HF cards, blogs and platform docs, the following are not mentioned at all (beyond Promptfoo plugin names in K2 Table 5): CBRN uplift or bio/chem capability evaluations; red-teaming by external experts (K2 red-team is tool-automated + internal human review); refusal calibration / over-refusal on benign prompts for Kimi models; multilingual safety breakdown (K2 used EN+ZH prompts but reports no per-language numbers); agentic safety / agent hijacking / prompt-injection-in-tools (K2 explicitly says tool-related plugins have "limited relevance" for base LLMs and K2.5/K3 report nothing); alignment, deception, scheming, sabotage, sycophancy evaluations (K2 only penalises flattery in RL rubrics); hallucination beyond factuality benchmarks is covered (FACTS/HHEM/FaithJudge/Faithfulness); bias/fairness benchmarks (no BBQ or similar); privacy beyond the Promptfoo "Privacy" rows; child safety (only as an aggregated Promptfoo plugin); content-moderation or guard models (none published; ToS mentions "safety detection" without detail); autonomy/ARA, self-replication, CoT monitorability, eval awareness, sandbagging, reward-hacking evaluations; K2.5, K2.6, K2.7 Code: no safety evaluation of any kind.

## Safety training and mitigations

- Safety RL environment (K2 report §3.2.1, verbatim): "Our work to enhance the safety begins with a human-curated set of seed prompts, manually crafted to encompass prevalent risk categories such as violence, fraud, and discrimination. To simulate sophisticated jailbreak attempts (e.g., role-playing, literary narratives, and academic discourse), we employ an automated prompt evolution pipeline with three key components: Attack Model ... Target Model ... Judge Model ... Each interaction is assessed using a task-specific rubric, enabling the judge model to provide a binary success/failure label."
- Self-critique rubric reward (K2 §3.2.2): alignment "with nuanced human preferences, including helpfulness, creativity, depth of reasoning, factuality, and safety" via the K2 critic scoring against "core rubrics (Appendix F.1), which represent the fundamental values of our AI assistant that Kimi cherish, prescriptive rubrics (Appendix F.2) that aim to eliminate reward hacking, and human-annotated rubrics". Core rubrics: Clarity and Relevance; Conversational Fluency and Engagement; Objective and Grounded Interaction (penalises "unwarranted flattery or excessive praise directed at the user ... attempts to curry favor through compliments"). Prescriptive rubrics: no "Initial Praise", no "Explicit Justification". Self-reported limitation (F.3): rubric "may favor responses that appear confident and assertive" and penalises hedging such as "this may not be accurate" — a sycophancy-adjacent and calibration trade-off acknowledged by the lab.
- K2.5 (report §RL): "Generative Reward Models (GRMs) that provide granular evaluations aligned with Kimi's internal value criteria" and "To mitigate reward hacking and overfitting to a single preference signal, we employ multiple alternative GRM rubrics tailored to different task contexts." No safety data, filters or refusal training described.
- K3: no description of safety training, data filtering, or guardrails anywhere in the 47-page report.
- Data filtering: no statement on toxicity/CSAM/PII filtering of pre-training data in any report; Kimi-VL/K2.5 only limit synthetic captions "to mitigate hallucination".
- Guard models / system prompts: none published. Platform ToS §3.3 forbids "Using variants, random characters, homophones, or other means to evade safety detection" and removing "identification marks of artificially generated content that we have labeled, including both explicit and implicit" — implying an input/output safety filter and AI-content watermarking on the hosted API, undocumented.
- Constitutional-style methods: none; the closest artefacts are the K2 Appendix F rubrics quoted above.
- Open-weight mitigations: licenses contain no acceptable-use restrictions; Kimi K3 License only says "Licensee's use of the Software must comply with applicable laws and regulations." Third-party finding (Yong et al. §6.3): "<$500 of compute and about 10 hours" sufficed to cut HarmBench refusals from 100% to 5% while retaining capability.

## Monitoring, frameworks and governance

- Frontier-safety / responsible-scaling-style policy: NONE published by Moonshot (checked moonshot.ai, kimi.ai/blog, platform docs index, GitHub org, HF cards). The K3 report's only forward-looking governance sentence: "We regard our evaluation as a lower bound on capability. What Western system cards cover that Moonshot's documentation does not:
- CBRN uplift trials with experts, bio/chem knowledge benchmarks (VCT, LAB-Bench, WMDP), wet-lab protocol troubleshooting — absent (K2 only aggregates a "Chemical&Biological Weapons" Promptfoo plugin into a "Criminal" pass rate). - CoT monitorability / faithfulness: absent (K2 Thinking/K2.5/K3 all expose reasoning; nothing on monitorability).

- Child safety, CSAM, minors: absent beyond ToS clauses and one aggregated Promptfoo plugin.
