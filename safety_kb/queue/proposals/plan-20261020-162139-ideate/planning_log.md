- Sunil et al., *Memory Poisoning Attack and Defense on Memory Based LLM-Agents*, arXiv:2601.05504, first submitted 2026-01-09. This studies memory-poisoning robustness and defenses, including effects of pre-existing legitimate memories. It establishes that memory poisoning itself is not novel. Our proposal isolates source attribution crossed with memory carrier on the specified catalog checkpoints, with fixed content and utility controls.

Statistical and feasibility decisions

- Use 1,000 base items for a 10-percentage-point interaction, not 1,000 correlated turns masquerading as items. With SD of the item interaction equal to 1.0, the normal approximation gives about 88% two-sided power to distinguish a true 0.10 effect from zero; the design is not guaranteed to pass its point-estimate threshold when the true effect is exactly that threshold. Both jobs require power curves and template-level sensitivity. Seeds and authorized twins remain within base-item clusters.
- The 0.03 utility/FPR requirements are guardrails with explicit noninferiority/equivalence intervals, not claims that any 3-point effect is detectable with arbitrary discordance. Wide guardrail intervals block the finding. Bounded nulls require the registered 90% interaction interval inside +/-0.05; a p-value above .05 alone is inconclusive.
- Main claims are checkpoint-specific. Secondary checkpoint/reference-judge tests use Holm correction. The primary tests are prespecified per separate research question; no post-hoc best-model selection. There are no temporal drift claims.
- Memory job: 12,000 main continuations plus 2,400 sampling diagnostics and 400 full-history diagnostics, 14,800 total. At the fixed generation caps this is approximately 9.47 million output tokens, under 18 inference hours at 150 aggregate tokens/s. Development throughput is a feasibility gate, not a reason to shrink confirmatory n. One 40GB GPU; $0 evaluation API spend.
- Auditor job: 8,000 main records, 400 action-only diagnostics, 400 repeated-positive diagnostics and 200 calibration records per auditor, 9,000 calls each. Two local auditors run sequentially; one Azure reference judge uses a $20 cap with a 20% retry reserve and actual deployment-price check before execution. At 192 output tokens the local ceiling is approximately 3.46 million tokens. No free-form actor generation or multi-turn agent trajectories are needed.
- A single primary decision is preferable to a multi-turn task here: it reduces the old DeepSeek scaffold's parse/utility confound. Native reasoning is preserved for DeepSeek and unfinished reasoning never earns refusal credit. All missingness and cutoff cases remain visible.
- No human answers are assumed. Synthetic labels derive from replayable permission tables, not claimed human annotations. LLM judges cannot overturn executable gold. Invalid JSON is separated from a substantive verdict and cannot manufacture the interaction.
